# Dance Studio

マネキンが踊る**無音動画**を作るアプリ。そのまま完成品にするものではなく、
Domo AI のような映像変換サービスに通してキャラクターに置き換えるための
**素材動画**を作るのが目的。音は変換が終わったあとに動画編集側で合わせる。

公開先: https://dopagakiorchestra.github.io/dance_studio/

## 使い方

1. BPM・拍子・小節数・くり返しを決める
2. 振り付けが自動で組み上がるので、気に入らなければ「引き直す」
3. ブロック単位で振りを差し替える（手で選んだところは引き直しても残る）
4. 「動画を書き出す」

手元の曲を読み込むと、プレビューをその音に合わせて見られる。
この音は書き出す動画には**入らない**。

## 開発

```sh
npm install
npm run dev      # 開発サーバ
npm test         # テスト
npm run build    # 型チェック + ビルド
```

React + Vite + TypeScript。実行時の依存は react / react-dom だけ。

## 構成

```
src/
├─ dance/            振り付けとマネキン描画（音楽に依存しない中核）
│  ├─ skeleton.ts     骨格、順運動学、左右反転、ポーズ補間
│  ├─ moves.ts        8カウント単位の振りパーツ辞書
│  ├─ choreo.ts       曲構造からパーツを並べる生成ロジック
│  ├─ sampler.ts      時刻→ポーズ（補間・繋ぎ・ビートの上下動）
│  ├─ render.ts       canvas描画（投影、画角の自動決定、配色）
│  └─ video.ts        canvas.captureStream + MediaRecorder
├─ components/DanceStudio.tsx  プレビュー・設定・ブロック一覧・書き出し
├─ audio.ts          音源ファイル再生（プレビュー同期用。動画には入れない）
├─ project.ts        設定モデル、localStorage、共有リンク
├─ compat.ts / save.ts / mp4.ts   保存まわり（iOSの癖対応）
└─ App.tsx           画面全体

tests/dance.test.ts, tests/project.test.ts
```

## 設計上の決定

変える場合は、まず理由を確認すること。

- **入力は BPM・拍子・小節数・くり返しの4つだけ。** 振り付け生成にコード進行や
  メロディは使っていないので、音楽理論のコードは持ち込んでいない
- **ポーズは関節の位置ではなく回転で保持。** 補間しても骨の長さが変わらず、
  左右反転が符号反転（Y,Z を反転、X はそのまま）で済むため
- **肘が曲がるのは X（前後）と Z（横）だけ。** 前腕は -Y 方向に伸びているので、
  Y 回転は軸まわりのひねりにしかならず見た目が変わらない。ここを取り違えて
  肘の指定19箇所が無効になっていたことがある。`elbow()` / `elbows()` を使い、
  生の配列で前腕を書かないこと（テストで検出される）
- **肘は伸ばし切らない。** 既定で少し曲げ（`ELBOW_REST`）、腕を上げた分だけ
  sampler が追加で緩める（`ELBOW_SOFT_MAX`）。伸び切った腕は棒に見える。
  振り付け側が大きく曲げているところには手を出さない
- **キレは「速く動く」ではなく「速く動いて止まる」で作る。** キーフレーム間を
  丸ごと使って動き続けると、どれだけ鋭い曲線を使っても体操にしか見えない。
  `snap`（ダイナミクス）が到達を早めて残りを静止に回し、行き過ぎてから戻り、
  振り幅・上下動・繋ぎの詰めまでまとめて動かす
- **振り幅の拡大は上半身だけ。** 脚と腰には掛けない。`weight()` が足の位置を
  角度で打ち消していて、`turnHalf` は hips の回転量そのものでターンを作って
  いるので、一律に倍率をかけると足が浮いたり回転角が変わったりする
- **画角の走査は 0.05 カウント刻み。** 粗いと、速い動きの行き過ぎた一瞬を
  跨いで見落とし、本番でそのコマだけ手足が画面外へ出る（実際に踏んだ）
- **ビートに乗った上下動が最重要。** これが無いと「ポーズの連続」に見える。
  腰を沈めた分だけ膝を曲げて足首位置を保つ（太もも α・膝 2α）
- **上下動は左右非対称にする。** ゆっくり伸び上がって素早く落ちる。対称な cos
  で上下させると浮いて見え、落ちを詰めると重さが出る（`DROP_SHARE`）
- **体の連鎖（腰→胸→肩→手先）で到達を遅らせる。** 全関節が同時に到達すると、
  人形が一斉に折れ曲がったように見える。これが硬さの正体。
  遅れを入れても**手先の最高速度は上がらない**（通る距離も時間も変わらないため）
  ので、映像変換のリスクを増やさずにキレを足せる数少ない手段
- **キメのブロックだけ繋ぎを狭くする。** 通常の繋ぎ幅だと締めの前後が常に
  クロスフェードに食われ、キメが丸まる。狭くするほど手先が速くなるので、
  「動きが飛ばない」テストの実測値を見ながら 0.14 カウントに置いてある
- **8カウントの繋ぎは境界の前後に均等なクロスフェード。** 後ろだけで繋ぐと
  手先の速度が3倍近くになり、映像変換で破綻する
- **画角は振り付け全体を先に走査して決める。** 手足が画面外に切れないため。
  動画1本の中では固定
- **動画は無音。** 変換サービスを通すと音は落ちるか尺がずれるので、音は別管理
- **形式は H.264 の MP4 を最優先、無理なら WebM。** コーデック指定なしの
  `video/mp4` を上位に置くと VP9 入り MP4 が返ってきて、拡張子が .mp4 なのに
  多くのツールで開けないファイルになる

## 既知の制約

- 録画は実時間かかる（MediaRecorder の仕様）。裏タブだと rAF が止まるので、
  書き出し中はこのタブを開いたままにする必要がある
- 出力ファイルは尺が「不明」として記録される。ブラウザ録画では避けられない。
  ffmpeg を通すサービスなら問題にならない
- **動きは「よくできた体操」レベル。** 手作りパーツの組み合わせなので、
  プロの振付師のタメや間は出ない。映像変換は絵柄を変えるが動きの硬さは残る
- **キーフレームが表拍にしか無い。** 146個すべてが整数カウント上にあり、
  「1 と 2 と」の“と”が1つも無い。キレの多くは裏拍の当て方で決まるので、
  ここは伸びしろとして残っている（moves.ts に書き足す作業）
- **手先の速度は既定でかなり速い。** ダイナミクス 0.75 で最高 14 身長/秒、
  1.0 で 22 身長/秒（0 のときは 5.5）。映像変換がフレーム間で追随できるかは
  未検証なので、破綻したらこのスライダーを下げて調整する

## 公開

`main` への push で GitHub Actions がテスト・ビルドして Pages に公開する
（`.github/workflows/deploy.yml`）。Pages が未設定でもワークフローが自分で
有効化する。ただし**無料プランでは Public リポジトリでないと Pages が使えない**。

## 検討中

実際に踊った8カウントを MediaPipe Pose で取り込んでパーツ化する拡張。
生成の枠組みはそのまま使えるので、パーツの中身だけ本物の動きに差し替えられる。
